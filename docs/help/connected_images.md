# X（旧Twitter）連結・多分割画像の自動パズル復元 (Connected Images)

X（旧Twitter）では、1枚の高解像度イラストを最大4枚に分割して投稿する文化が広く定着しています。  
MangaMeYeah! は、分割されて投稿された連番画像を高度な画像相関解析により自動検知し、本来の1枚の大きなイラストとして自動結合表示します。

---

## 1. 対応している分割パターン

| パターン | グリッド | 特徴・用途 |
| :--- | :---: | :--- |
| **横2枚連結** (見開き) | 2列 × 1行 | 横長のワイドイラストや見開き漫画 |
| **縦2枚連結** | 1列 × 2行 | 縦長の全身イラストや4コマ漫画 |
| **横3枚連結** | 3列 × 1行 | 横長パノラマ・ヘッダー画像 |
| **縦3枚連結** | 1列 × 3行 | 縦長スクロール漫画 |
| **横4枚連結** | 4列 × 1行 | 超ワイドパノラマイラスト |
| **縦4枚連結** | 1列 × 4行 | 縦長の長尺キャラクター設定画・衣装紹介など |
| **縦横2×2連結** (4枚組) | 2列 × 2行 | X（Twitter）標準の4枚グリッド投稿 |

## 2. 24通り全探索パズル復元アルゴリズム

### タイムラインでの意図的な並べ替えによるシャッフル問題
X（Twitter）では、タイムライン上で別の絵に見せたり意外性・誤解を起こさせる仕掛け（視覚トリック）を演出するために、画像をアップロードした後にポスト編集機能等を使って意図的に画像の並び順を変更してから投稿を確定させるケースがあります。  
この場合、ダウンロードされたファイル名の連番（アップロード順など）と本来イラストとして正しくつながる配置（`[左上, 右上, 左下, 右下]`）との間に食い違いが生じ、ファイル名順のままでは絵柄がバラバラになってしまいます。

MangaMeYeah! では、4枚の画像に対して **$4! = 24$ 通りの全配置順列を瞬時に生成** し、以下の接合シーム（境界線）の色差と相関をミリ秒以下で総当たり照合します：
- 左上 と 右上 の接合境界
- 左下 と 右下 の接合境界
- 左上 と 左下 の接合境界
- 右上 と 右下 の接合境界

最も接合誤差（MAE）が小さく相関が高い組み合わせを自動決定して配置するため、**タイムライン演出のために意図的に並べ替えられた画像であっても、元の正しい位置に自動でパズル復元** されます。

## 3. 誤検出防止フィルター（白余白・単色背景対策）

### なぜ誤検出が起きるのか？
青空や海、白いスタジオ背景など、背景が一様なイラストが連番で並んでいる場合、エッジ（境界線）の色差だけを単純に比較すると、まったく別の画像同士であっても「色差がゼロに近い」として誤って結合判定されてしまうリスクがありました。

### MangaMeYeah! の防御アーキテクチャ
1. **接合シームのエッジ色彩標準偏差 (`seamStdDev >= 7.0`)**:
   純白や単色の余白枠など、テクスチャや色の変化が存在しないシームは「結合すべき絵柄ではない」と判定して即座に除外します。これにより、白背景の単体イラストが横2枚や横4枚に誤認識される現象を完全に排除しています。
2. **縦横双方向スコアリング**:
   正方形や同一寸法の分割画像（例: 縦4枚の衣装シート）では、横方向・縦方向の双方のシーム品質スコアを算出して比較し、実際に絵柄が連続している方向（縦分割）を優先して採用します。
3. **見開きずれ自動補正**:
   見開き（2ページ）表示の途中で連結画像の開始位置が現れた場合、前の画像に連結画像の1枚目が巻き込まれて分断されないよう、前ページを自動的に単ページ化して位置ずれを解消します。
